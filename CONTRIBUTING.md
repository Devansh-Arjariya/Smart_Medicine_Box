# Contributing to Smart Medicine Box Pro (SMB)

Thank you for your interest in contributing to **Smart Medicine Box Pro**! We welcome bug reports, feature requests, and code contributions to improve medication adherence and smart health monitoring.

---

## Code of Conduct
Please maintain a respectful, inclusive, and collaborative environment. Be thoughtful, constructive, and kind in all discussions, issues, and pull requests.

---

## How Can I Contribute?

### 1. Reporting Bugs
- Ensure the bug was not already reported by searching existing GitHub Issues.
- Provide a clear and descriptive title.
- Detail the exact steps to reproduce the issue, expected outcome, and actual behavior.
- Include browser type, device information, and console error logs if available.

### 2. Suggesting Enhancements
- Open a feature request issue with an explanation of why the feature would be valuable.
- Include mockups, UI concepts, or technical proposals if applicable.

### 3. Pull Requests (PRs)
1. **Fork** the repository and clone your fork locally.
2. Create a descriptive feature branch:
   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/your-bugfix-name
   ```
3. Test your changes locally across different screen sizes (mobile, tablet, desktop) and themes (Light, Dark, Green).
4. Commit your changes with clear, semantic commit messages:
   ```bash
   git commit -m "feat: add medication reminder sound toggle"
   ```
5. Push to your branch:
   ```bash
   git push origin feature/your-feature-name
   ```
6. Open a Pull Request against the `main` branch with a summary of changes.

---

## Code Style & Standards
- Use semantic HTML5 elements.
- Maintain CSS variables for consistent theming and responsive design.
- Keep JavaScript modular, well-commented, and resilient with fallback error handling.
- Avoid committing private API credentials or personal Firebase configurations.
